# JD Copilot — AI 需求对齐助手
## 案例摘要 · Connor · AI 产品经理

---

### 一句话定位
> **帮 HR 从"我要一个前端"开始，通过 AI 对话搞清楚真实需求，生成一份靠谱的 JD。**

---

### 为什么做这个？

**根因洞察**：招聘链路中，简历筛选是下游问题。真正的根因是 —— **JD 与用人部门真实需求的错配**。

```
JD 不对 → 筛选标准不对 → 来的人不对 → 面试被否 → 招来了也留不住
```

**市场空白**：Moka、北森、LinkedIn 都从"已有 JD"开始做（模板/筛选/匹配），没有人做 JD 之前的需求收集。

| 数据 | 来源 |
|------|------|
| 61% 招聘专业人士面临人才短缺 | SHRM Q3 2025 CHRO Outlook |
| 33% 新员工 6 个月内寻找新工作 | BambooHR 2023 |
| 错误招聘成本 = 年薪 30% | U.S. DOL |

---

### 解决方案

**JD Copilot** — 对话式需求收集 + 结构化 JD 生成

| 维度 | 做什么 | 不做什么 |
|------|--------|----------|
| MVP | 对话追问、需求文档、JD 草稿、质量评估 | 简历筛选、ATS 集成、候选人沟通 |

**Skill Card 六维框架**（Hello-Agents Ch12）：
- **Intent**：模糊需求 → 结构化岗位要求
- **Boundary**：不编造未提及要求，标注"待确认"
- **Quality Bar**：需求覆盖度 ≥ 80%、幻觉率 ≤ 10%

---

### 技术选型

| 决策 | 选择 | 理由 |
|------|------|------|
| Agent 范式 | **Plan-and-Solve + Reflection** | 先收集再生成，需要自校验防止幻觉 |
| 模型 | Llama 3.3 70B (NVIDIA NIM) | 响应快（~5s）、中文理解好、免费额度 |
| 部署 | Vercel Edge Runtime | 零运维、全球低延迟、SSE 流式 |
| 上下文工程 | GSSC 流水线 | Gather-Select-Structure-Compress |

**幻觉防控**（Hello-Agents Ch9）：
- Prompt 层：禁止编造 + 标注来源
- 结构层：JSON Schema + 6 层兜底解析
- 输出层：自检 checklist + 置信度评分

---

### Demo 真实交互示例

**输入**：`前端工程师`

**AI 追问**（Plan 阶段）：
1. 负责什么项目？（C 端/B 端/内部工具）
2. 技术栈要求？（React/Vue/Angular）
3. 团队角色？（独立/协作）
4. 经验要求？（年限/行业/大厂）
5. 排除项？
6. 薪资范围？

**HR 回答**：`B 端 SaaS，React + TypeScript，团队 5 人，独立负责模块，3 年以上，不要频繁跳槽，25K-40K`

**AI 输出**（Solve + Reflect 阶段）：
- 📋 需求文档：3 条硬性要求 + 排除项 + 薪资（标注来源）
- 📄 JD 草稿：岗位描述 + 职责 + 要求 + 加分项
- 📊 质量评估：覆盖度 90%、准确度 85%、幻觉率 5%、置信度 0.88

### 诚实声明

- ✅ Demo 使用真实 LLM API，非预设脚本

- ⚠️ 行业 JD 数据库尚未建立，当前依赖 LLM 通用知识
- ⚠️ 偏见检测仅 Prompt 层，需独立监控模块

---

### 我学到了什么

1. **根因分析 > 症状治疗**：简历筛选是下游，需求对齐才是源头
2. **市场空白 = 机会**：所有竞品都在做"已有 JD 之后"的事
3. **Plan-and-Solve 比 ReAct 更适合**：JD 生成不需要工具调用，需要先收集后生成
4. **幻觉防控是系统工程**：不能只靠 Prompt，需要 Prompt + 结构 + 自检三层
5. **诚实 > 包装**：未验证的数据标注"待验证"，面试追问不会穿
