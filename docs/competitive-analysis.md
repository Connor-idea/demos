## 二、关键发现：市场空白

**所有竞品都在做"简历筛选"和"候选人匹配"，但没有人专注做"需求收集"。**

```
招聘漏斗：
  需求产生 → JD 编写 → 渠道发布 → 简历收集 → 筛选 → 面试 → 录用
      ↑                    ↑              ↑
      │                    │              │
  【空白区域】          Moka/北森       Moka/LinkedIn
  没有 AI 工具          JD 模板功能     简历筛选功能
  帮 HR 做这一步        （模板化，非     （关键词匹配，
  （需求对齐）          个性化）        非理解型）
```

**具体空白**：
- Moka 的 JD 功能：提供行业 JD 模板，HR 选择模板后修改 → 没有"帮 HR 理解需求"的过程
- 北森的胜任力模型：基于岗位模型匹配候选人 → 但岗位模型本身怎么来的？还是 HR 手动定义
- LinkedIn 的 JD 优化：基于数据建议 JD 改进 → 但前提是已经有一份 JD 草稿

**JD Copilot 的差异化**：
- 不是"帮你写 JD"（模板化），而是"帮你搞清楚要什么样的人"（对话式）
- 不是"帮你筛简历"（下游），而是"帮你定义筛选标准"（上游）
- 不是"给你模板"（静态），而是"引导你思考"（动态）

## 四、为什么竞品没做"需求收集"？

1. **技术难度**：需要对话式 AI 能力，传统的关键词匹配不够
2. **用户习惯**：HR 习惯了"搜 JD 模板"的方式，需要教育市场
3. **商业模型**：SaaS 产品追求"全流程覆盖"，单点功能不够吸引付费
4. **数据壁垒**：需要行业 JD 数据库 + 岗位胜任力模型

**我们的优势**：
- LLM 的对话能力让"引导式需求收集"成为可能
- 专注单点功能，做到极致（小而美）
- 不需要"全流程覆盖"，可以作为现有 ATS 的补充工具

```
  ─────────────────────┼────────────────────────

                    低复杂度

    （全流程）          （单点极致）
```

**JD Copilot 的定位**：低复杂度、单点极致、专注需求对齐。
